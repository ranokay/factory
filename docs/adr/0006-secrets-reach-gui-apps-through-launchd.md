# Secrets reach Dock-launched apps through launchd env

The Factory Repo holds the MCP registry (`mcp.json`) and its renderer (`scripts/mcp-sync.py`) because the registry used to live in `~/.agents` with a literal Context7 key, and a public repo must not hold secrets. Registry entries name a secret header as an environment variable plus an `op://` reference, never a value. The renderer writes each harness's native env-var syntax: `${VAR}` in Claude Code's `~/.claude.json`, `{env:VAR}` in OpenCode's config, and `bearer_token_env_var` in Codex's `config.toml`. T3 Code has no MCP config of its own; it drives those three agents, so rendering their configs covers it.

Dock-launched apps inherit `launchd`'s environment, not a shell profile, so a `~/Library/LaunchAgents/dev.factory.secrets.plist` runs `mcp-sync --env` at login. The agent reads each `op://` reference and calls `launchctl setenv`, which leaves the value in `launchd` memory and out of every file. The plist bakes in the absolute mise Python that bootstrap resolved, so `bootstrap --check` fails when that interpreter disappears or the plist drifts; a `mise prune` or a Python bump is repaired by rerunning bootstrap. `KeepAlive` with `SuccessfulExit = false` and a `ThrottleInterval` retries until 1Password is unlocked, and each failure lands in `~/Library/Logs/factory-secrets.log` rather than leaving the variable silently unset.

The renderer rewrites only the servers the registry manages, leaves every other server alone, and removes a server only when the registry lists it under `retired`; that is how the dead `caveman` entry goes without touching `cua`, `rea` or `sonarqube`. A harness config that does not exist yet, because the harness has never run, is created as a minimal valid config holding only the registry servers that target it, so bootstrap readies a fresh Mac even for harnesses opened later; an absent config counts as drift until it is rendered. Creating the file beats skipping it, which leaves a first-run harness without Context7 until the next bootstrap, and beats failing the render, which would stop bootstrap on a fresh Mac for a harness nobody has opened yet. Drift is judged only on the managed entries: Claude Code rewrites unrelated session keys in `~/.claude.json` continuously, so a whole-file comparison reports permanent drift and churns backups. Every rewritten config keeps a dated `backup-` copy and its file mode. GitHub SSH is a separate decision in ADR 0007.

Shell profiles were rejected because they never reach a Dock launch. Harness configs with resolved values were rejected because they recreate the leak. Resolving the secret inside each harness was rejected because Claude Code and OpenCode have no equivalent of Codex's header helper, so `launchctl setenv` is the one mechanism that works for all of them.

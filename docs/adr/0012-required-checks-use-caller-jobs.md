# Required checks use caller jobs, not reusable workflows

GitHub names a reusable-workflow check `<caller job> / <callee job>`, so a reusable call cannot produce a single context. The required checks therefore run as caller jobs named `Lint`, `Security` and `Tests` in the `Gates` workflow, and `OCR` in the `AI Review` workflow, with the shared steps in the composite actions `.github/actions/gates` and `.github/actions/ocr-review`. A consuming repository can call the actions, but it owns the caller job and therefore the check name; the Project Template callers pin the first release carrying both actions (v0.5.0, issue #131).

The `Gates` action takes a `group` input and the three `Gates` jobs run in parallel with their own mise cache. `Lint` runs formatting and config checks, `Security` runs secrets, supply-chain and the local Codacy gate, and `Tests` runs every test suite and fixture. The rule is unchanged by issue #146: the split made each check say what it does, but a reusable workflow still cannot own the context.

The alternative, keeping the reusable workflows and accepting the nested contexts, fails the requirement that the checks read `Lint`, `Security`, `Tests` and `OCR`. The cost is that a consumer must add caller jobs and reconcile its ruleset; until it does, the old contexts are gone and its PRs are blocked rather than admitted without the checks. The live ruleset swaps the old contexts for the new ones in one atomic update while the new checks are green, with Codacy in the same payload.

# Verification-skill maintenance follows app commits, not the calendar

The weekly `verify-skill:maintain` command files one `ready-for-agent` issue per repository whose app changed since its verification skill was last maintained. Last maintenance is the newer of the last commit touching any `.agents/skills/verify-*` path and the head SHA recorded in the most recently closed maintenance issue (`<!-- factory:verify-maintenance head=<sha> -->`). App changed means the default branch has a later change outside `.agents/skills` and `.claude/skills`. An open issue carrying the marker blocks a duplicate.

A `clean` maintenance pass ships nothing, so a commit-only rule re-files every week. Recording the head when the issue is filed and treating the most recently closed issue as maintenance makes closing a clean pass silence the next week, while a new app commit after that head files again. The alternative, a fixed cooldown, either re-files after a clean pass or hides a real change. The cost is a paged GitHub search per state per repository and a machine-readable head in the issue body; a missing or rewritten head falls back to the skill commit with a warning. The default branch comes from `origin/HEAD`, never a hard-coded `main`.

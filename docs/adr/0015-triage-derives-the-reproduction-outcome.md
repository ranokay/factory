# Triage derives the reproduction outcome from observed checks

A bug report in a Personal Project is reproduced through the project's `verify-<app>` CLI. The triager maps the reported steps to commands the CLI lists under `commands`, gives `scripts/triage.py reproduce` one or more observations (`<step>:<key>=<value>` or `<step>:exit=<n>`), and the script captures every step's exit code and JSON. The outcome is `reproduced` only when every observation matches. The script posts one evidence comment before it applies `bug` with `ready-for-agent` or `needs-info`, and it deletes its local evidence after both succeed.

A declared outcome lets an agent label a bug ready for an agent without a check, and a comment quoting the report can carry mentions, links and markup from an untrusted author under the Factory's name. Deriving the outcome from captured output and referencing the issue only by number and body timestamp keeps the claim checkable and the comment the Factory's own words. The alternative, letting the agent choose the outcome and paste the report, needs a reviewer to re-read untrusted prose to trust a label. The cost is one observation per claimed symptom and a reproduction plan the agent writes from the report without executing it; a report too vague to map to CLI commands reaches `needs-info` instead.

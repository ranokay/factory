# Merges run through one guarded script

An ordinary pull request merges through `skills/merge-pr/scripts/merge`, whose Merge Guard refuses an author outside `factory_authors` or a head from another repository, then runs `gh pr merge` with `--match-head-commit` and the repository's method. `merge-pr` and `babysit-pr` both call it, and `request-advisory-reviews` uses a byte-identical copy at `skills/babysit-pr/scripts/merge_guard.py`; the identity test in `merge-test.py` fails if the copies drift, so the Outside Contributor definition has one enforced home.

The prose rule "never auto-merge an Outside Contributor PR" relied on every skill reading it at merge time; a script makes the refusal happen whatever the prose says. A Sync PR keeps executing only the `sync-upstream merge-command` output, because that printed command carries the verdict gate and the review-ruleset `--admin`; a Sync PR is authored by ranokay in the repository itself, so the guard has nothing to add. The alternative, a workflow assertion, runs after the fact and cannot stop a merge that a local agent already performed.
